# Операторский интерфейс

## Purpose

Обеспечивает проверяемое поведение блока B05: операторский интерфейс, в составе единой системы подсчета грузовых мест при загрузке вагонов.

## ADDED Requirements

### Requirement: WC-B05-R01 — Авторитетное состояние

Система SHALL отображать сессию, типы, итог, качество, время и отдельно план и видимую занятость.

#### Scenario: WC-B05-R01-S01 — Проверка 1
- **WHEN** план отсутствует или равен нулю
- **THEN** процент к плану=null, вымышленный объем не рисуется

#### Scenario: WC-B05-R01-S02 — Проверка 2
- **WHEN** WebSocket переподключился после потери сообщений
- **THEN** получен HTTP snapshot, счет не восстановлен догадками браузера

### Requirement: WC-B05-R02 — Ручные действия

Система SHALL требовать тип и причину корректировки и подтверждать успех только после applied.

#### Scenario: WC-B05-R02-S01 — Проверка 1
- **WHEN** форма отправлена дважды
- **THEN** один command_id и одна дельта

#### Scenario: WC-B05-R02-S02 — Проверка 2
- **WHEN** аналитик вызвал изменяющий API напрямую
- **THEN** 403 на сервере

### Requirement: WC-B05-R03 — Автономный UI

Система SHALL обслуживать тот же интерфейс из Edge независимо от центрального Nginx и авторизации.

#### Scenario: WC-B05-R03-S01 — Проверка 1
- **WHEN** центр и Nginx остановлены
- **THEN** локальный HTTPS8443 и аварийная учетная запись работают с аудитом

#### Scenario: WC-B05-R03-S02 — Проверка 2
- **WHEN** запрошено принудительное завершение
- **THEN** показаны вагон, счет, отклонения; причина обязательна
