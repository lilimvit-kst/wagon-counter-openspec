# Решение B01 — Среда, зависимости и CI

## Context

Прочитать AGENTS.md и разделы 2,10/B01,11/2–8 исходного ТЗ. Зависимости: B00. Основные решения и стек — docs/architecture.md и docs/adr/.

## Goals / Non-Goals

Реализовать наблюдаемое поведение delta spec через предусмотренные интерфейсы. Функция на заглушке не подтверждает интеграцию с реальными сервисами.

## Decisions

Ниже сохранено подробное задание этого блока из ТЗ:

Создать deploy/compose.infra.yml, будущий compose.release.yml, Dockerfile.backend, Dockerfile.vision, Dockerfile.web и отдельный Dockerfile.ocr. Реализовать scripts/check_env.sh, scripts/lock_dependencies.sh и CI.

Установить и проверить инфраструктуру по разделу 11. Зафиксировать package-lock, Python locks, образы и SBOM/список лицензий. После этого сборки приложений выполняются из locks; bootstrap-диапазоны зависимостей не используются в релизе.

Готовность: чистая машина собирает одинаковые приложения из выбранного commit, проходят импорты и тестовый экспорт; PostgreSQL, MQTT и MediaMTX доступны только на предусмотренных адресах. После перезапуска инфраструктуры данные сохраняются.

Один Pydantic источник DTO, общие fixtures и генерация TypeScript; домен не импортирует FastAPI/ORM/CV/MQTT. Только Edge подтверждает счет; чистый reducer используется центром. Для изменяемого учета указать точную транзакцию, порядок дедупликации, контроль версий и восстановление. Для видео указать PTS, геометрию и измерение возраста. Не придумывать внешний контракт ERP и недоступные ROI.

## Risks / Trade-offs

Доступные входные данные и разрешенные режимы указаны в docs/field-inputs.md. Наличие скрипта обучения не заменяет принятую модель. B09 допускает проверенный ручной режим, B10 — visible_occupancy. Скорость CPU и метрический объем не объявляются гарантированными.

## Migration Plan

Новый код подключить к существующему инкременту. При изменении persistent данных — отдельные миграции Edge/центра, согласованная резервная копия, проверка на копии, обновление читателей и откат с учетом новых событий. Если данных это не касается, записать обоснованное отсутствие миграции.

## Verification

Каждый Scenario связать с фактически выполненным тестом или протоколом стенда. Готовность определяется приведенным выше критерием блока. Зафиксировать версии, среду, команды, результаты и ограничения в отчете; OpenSpec validate не доказывает работу приложения.
