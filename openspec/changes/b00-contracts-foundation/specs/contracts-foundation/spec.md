# Контракты и каркас

## Purpose

Обеспечивает проверяемое поведение блока B00: контракты и каркас, в составе единой системы подсчета грузовых мест при загрузке вагонов.

## ADDED Requirements

### Requirement: WC-B00-R01 — Единицы учета

Система SHALL учитывать bag_25, bag_50, bundle_5kg, bundle_10kg и unknown, считая пачку одним местом.

#### Scenario: WC-B00-R01-S01 — Проверка 1
- **WHEN** приняты две разные пачки
- **THEN** total_units=2, номинальная масса 100 кг

#### Scenario: WC-B00-R01-S02 — Проверка 2
- **WHEN** есть подтвержденное unknown
- **THEN** оно входит в итог; полная nominal_mass_kg=null

### Requirement: WC-B00-R02 — Идентификаторы и версии

Система SHALL сохранять UUID, UTC/RFC3339 и wagon_id строкой из восьми ASCII-цифр; различать версии контракта, модели, конфигурации и управления.

#### Scenario: WC-B00-R02-S01 — Проверка 1
- **WHEN** номер 01234567 валиден
- **THEN** ведущий ноль сохранен

#### Scenario: WC-B00-R02-S02 — Проверка 2
- **WHEN** неизвестная старшая schema_version или буквы в номере
- **THEN** сообщение отвергнуто до учета

### Requirement: WC-B00-R03 — Единая схема API

Система SHALL предоставлять согласованные JSON Schema, OpenAPI, TS-типы, ErrorResponse и общие fixtures.

#### Scenario: WC-B00-R03-S01 — Проверка 1
- **WHEN** схемы повторно сгенерированы из прежних DTO
- **THEN** нет diff, валидные fixtures принимаются Python и TS

#### Scenario: WC-B00-R03-S02 — Проверка 2
- **WHEN** в fixture отсутствует обязательное поле
- **THEN** обе стороны отклоняют пример

### Requirement: WC-B00-R04 — Канонизация и ключи

Система SHALL различать event_id, позицию журнала, ключ наблюдений и command_id и проверять hash повторного содержимого.

#### Scenario: WC-B00-R04-S01 — Проверка 1
- **WHEN** ключи одного JSON переставлены
- **THEN** канонический hash совпадает

#### Scenario: WC-B00-R04-S02 — Проверка 2
- **WHEN** тот же command_id имеет другой payload
- **THEN** конфликт без изменения счета
