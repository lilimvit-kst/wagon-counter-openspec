# Центр и надежная синхронизация

## Purpose

Обеспечивает проверяемое поведение блока B04: центр и надежная синхронизация, в составе единой системы подсчета грузовых мест при загрузке вагонов.

## ADDED Requirements

### Requirement: WC-B04-R01 — Непрерывный ACK

Система SHALL подтверждать только непрерывно сохраненную последовательность после commit центра.

#### Scenario: WC-B04-R01-S01 — Проверка 1
- **WHEN** доставка 1,3,2
- **THEN** после 3 ACK=1, после 2 ACK=3; три события применены один раз

#### Scenario: WC-B04-R01-S02 — Проверка 2
- **WHEN** ACK потерян после commit
- **THEN** повтор события дает ACK без повторной дельты

### Requirement: WC-B04-R02 — Подтверждение учета

Система SHALL сохранять Edge outbox до прикладного ACK нужного журнала, различая его и PUBACK.

#### Scenario: WC-B04-R02-S01 — Проверка 1
- **WHEN** брокер принял сообщение, PostgreSQL недоступен
- **THEN** outbox сохраняется, Edge продолжает учет

#### Scenario: WC-B04-R02-S02 — Проверка 2
- **WHEN** один ключ события пришел с другим hash
- **THEN** конфликт и инцидент без ложного подтверждения

### Requirement: WC-B04-R03 — Центральные команды

Система SHALL отправлять команды Edge и показывать queued до результата, не редактируя счет напрямую.

#### Scenario: WC-B04-R03-S01 — Проверка 1
- **WHEN** центр вернул HTTP202 при недоступном Edge
- **THEN** UI не объявляет изменение счета applied

#### Scenario: WC-B04-R03-S02 — Проверка 2
- **WHEN** потерялся command-result
- **THEN** повтор того же command_id не создает второй эффект

### Requirement: WC-B04-R04 — Журналы и восстановление

Система SHALL различать журналы при утрате БД и сверять состояние после восстановления связи.

#### Scenario: WC-B04-R04-S01 — Проверка 1
- **WHEN** создана новая SQLite после потери
- **THEN** новый journal_id, нумерация не переиспользует старую историю

#### Scenario: WC-B04-R04-S02 — Проверка 2
- **WHEN** центр вернулся после накопления событий
- **THEN** все сохраненные события переданы и сверены, outbox не удален по сроку
