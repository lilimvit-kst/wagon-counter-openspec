# Организация разработки

## Purpose

Определяет поставленный способ последовательного планирования и проверки изменений, позволяющий различать подготовленные требования и фактическую реализацию.

## Requirements

### Requirement: WC-SETUP-R01 — Последовательность

Репозиторий SHALL содержать исходное ТЗ с hash и проверяемый порядок B00–B14.

#### Scenario: Начальный комплект
- **WHEN** разработчик проверяет новый комплект
- **THEN** B00 доступен, B01 ожидает B00, продуктовые блоки planned

### Requirement: WC-SETUP-R02 — Доказательства

Проверка SHALL отклонять verified без заполненной структуры доказательств и завершенных задач.

#### Scenario: Необоснованный статус
- **WHEN** блок отмечен verified без verification
- **THEN** проверка завершается с ошибкой и называет отсутствующие данные
