# Правила агента — wagon-counter

Репозиторий подготовлен для последовательного написания кода по программному ТЗ 1.0. B00–B14 пока planned; планы OpenSpec не являются реализацией.

## Начало поручения

Прочитать docs/OPENSPEC_RULES.md, docs/ROADMAP.md, docs/architecture.md, docs/blocks.json. Выполнить python3 scripts/check_project.py --can-start Bxx. Прочитать разделы исходного ТЗ и все proposal/design/specs/tasks назначенного изменения, действующие main specs и отчеты зависимостей. Получить openspec instructions apply --change <change> --json.

Уточнения пользователя приоритетны. Уже порученную работу выполнять без повторных разрешений на рутинные действия. Техническую неоднозначность внутри требования разрешать самостоятельно и записывать. Если меняется бизнес-смысл и ответа нет, выполнить независимую полезную часть, затем задать конкретный вопрос. Подготовка правил не означает поручение сразу написать все приложение; реализация Bxx означает закончить его проверенный инкремент.

## Инварианты

- Только Edge меняет счет: один процесс/writer SQLite и одна очередь. Vision передает наблюдения, центр/UI — команды.
- Атомарно сохранять checkpoint наблюдений, crossing state, event, projection и outbox. Историю не переписывать; правка является событием.
- Четыре типа из ТЗ; пачка — одно место. unknown обозначает подтвержденное место неизвестного типа, а не сомнительное существование объекта. Неизвестные масса/объем — null.
- A→B=+1, B→A=−1; повторный перенос после возврата — новое crossing_id. Предсказание без детекции и новый трек в B не подтверждают загрузку.
- Сумма типов равна итогу, каждый тип неотрицателен. Переклассификация имеет нулевую общую дельту.
- UUID сессии создается до номера, wagon_id — строка из 8 ASCII-цифр. Одна незавершенная сессия на точку.
- Дедупликация повторной команды раньше проверки control_version; actor задает авторизация сервера. Финальное исправление создает revision+1.
- MQTT QoS1 допускает дубли. PUBACK не заменяет contiguous ACK после commit центра. Outbox не удаляется по сроку.
- ERP получает результат после полного watermark и сверки; неопределенный timeout требует ключа/поиска или ручной сверки.
- План, видимая занятость и метрический объем раздельны. CPU x86, две камеры 1080p/30; Jetson/GPU не обязательны. FPS и точность подтверждаются испытанием.
- Ручные OCR/двери предусмотрены. Объем требует отдельной приемки. Simulator/replay/shadow отделены от live; рабочая ERP в них выключена.

## Код и проверка

Python3.12: единые Pydantic DTO и чистый domain; FastAPI/ORM/CV/MQTT — адаптеры. Центр и Edge используют один reducer. TypeScript/React получают generated API types; браузер не владеет счетом. Стек и импорты — docs/architecture.md.

Изменение контракта сопровождается схемами, OpenAPI, TS, fixtures и обоими потребителями. Проверять поведение и риски, а не только наличие собственных функций. FakeERP/симулятор явно обозначены и используют настоящие интерфейсы. Не возвращать фиктивный успех незавершенной интеграции.

Секреты, видео, датасеты, БД, веса и рабочие логи не входят в Git. Не выполнять destructive миграции/restore на рабочих данных для проверки. Не сбрасывать чужие изменения и не делать force push.

## OpenSpec и завершение

Карта docs/blocks.json определяет реальную последовательность и статусы; штатная CLI не проверяет межблочные зависимости. Служебные навыки .agents/skills созданы OpenSpec; проектные правила находятся в этом файле, config.yaml и подробной инструкции.

[x] означает выполненную проверенную задачу. Перед verified: реальные тесты, отчет docs/blocks/Bxx.md, verification и npm run check. После этого архивировать change с синхронизацией и снова проверить. Наличие planning artifacts не означает готовый код. При отсутствующих данных отмечать выполненную часть и блокер, не подменять приемку заглушками.

Использовать небольшие осмысленные коммиты feat/test/docs/fix. Локальный коммит разрешен поручением. Для push должен быть определен remote и область публикации. В конце сообщить результат блока, фактические проверки, ограничения и следующий доступный блок.
